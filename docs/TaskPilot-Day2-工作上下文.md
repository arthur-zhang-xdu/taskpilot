## 2. 项目背景与既定范围

**TaskPilot：可评测的研发故障分析 Agent。**

典型需求：

> 分析 payment-service 在指定 30 天内的故障，统计最常见的三类问题，检索排障文档，生成带数据依据和来源引用的 Markdown 报告。证据不足时明确说明，不执行实际修复。

核心闭环：自然语言任务 → 有边界的工具调用 → 查询、统计、知识检索 → 报告与结果验证 → Trace → 独立评测。

第一版只覆盖故障查询统计、知识查询、综合报告。区分已知事实、可能原因与待验证事项，不能仅凭文档声称证明了真实根因。

技术路线：Python、FastAPI、Pydantic；后续 LangGraph、PostgreSQL、SQLAlchemy、Alembic、pgvector、Streamlit、pytest、HTTPX、Docker Compose、CI。先小闭环，再逐步引入组件。

约束：

- 统计交给程序，第一版不开放任意 SQL 或 Shell。
- Agent 执行与独立评测分离。
- 使用外部模型与 Embedding API，不绑定单一供应商。
- 起步单任务、低并发。
- 暂缓多 Agent、长期记忆、微调、MCP 服务端、真实自动修复、完整 Vue 前端和 Kubernetes。

总体里程碑：第 7 天工具调用链路；第 14 天带证据报告；第 21 天独立评测；第 28 天可部署展示；第 5 周补缺、实验整理与面试准备。

### B. 依赖管理

- 不在 Day 2 加入数据库、向量检索和大型 Agent 框架依赖。

### C. 配置管理

使用类型化 Settings 集中读取配置，建议字段：

```text
APP_NAME=TaskPilot
APP_ENV=development
LOG_LEVEL=INFO
LLM_API_KEY=
LLM_BASE_URL=
LLM_MODEL=
LLM_TIMEOUT_SECONDS=30
```

设计要求：

- 优先级明确：显式测试配置 / 环境变量 / 可选 `.env` / 默认值，以实际实现文档为准。
- `.env` 加入忽略清单，`.env.example` 只包含无敏感值的示例。
- Key 使用秘密字段类型或等效保护，不打印整个配置对象，不返回配置转储接口。
- 应用基础启动不依赖真实 Key；调用模型时再检查所需参数是否齐全。
- 超时必须为正数，日志级别限制为允许集合，非法配置给出可定位且不泄密的错误。
- `.env` 文件位置有明确规则，不依赖偶然的工作目录。
- 测试显式隔离真实 `.env` 和开发环境变量，避免误发真实模型请求。
- 不假定所有供应商都是同一种 API 协议，不擅自改变 Day 1 端点或模型。

### D. API 与健康检查

最小接口：

```http
GET /health/live
```

建议响应契约：

```json
{"status": "ok", "service": "TaskPilot"}
```

- 返回 HTTP 200 和稳定 JSON Schema。
- 只表达进程与应用请求处理链路存活。
- 健康接口不调用外部模型，不消耗 Token，不声称数据库或模型服务可用。
- Day 2 没有数据库等必要依赖时，无需虚设 readiness 接口。
- 保留默认 `/docs` 和 `/openapi.json`，供开发验证。
- 不存在的路由返回 404，避免无必要的统一异常处理覆盖框架行为。
- 不为展示请求校验额外增加无业务价值接口；如已有接口有请求模型，验证其 422 行为即可。

服务器运行命令示意，按实际布局校准并记录：

```bash
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

如采用纯工厂入口，则使用对应的 `--factory` 命令，不在文档留下不可执行入口。

从本地通过 SSH 转发访问服务器回环端口。默认不需要开放公网端口、设置域名、暴露数据库或启用宽泛 CORS。开发热重载仅用于开发。

### E. 测试与验证

优先覆盖能够发现实际错误的行为：

1. 应用在没有模型 Key、没有外网调用的情况下启动，健康接口返回约定结构。
2. 非法超时等配置会失败；环境变量覆盖规则按约定生效。
3. 配置与健康响应不泄露秘密。
4. 现有 Day 1 统计测试或小样本校验仍通过。
5. 真实启动 Uvicorn 后，健康接口与 OpenAPI 可访问。

健康接口测试无需过多变体，不编写仅镜像实现的测试。基本配置和健康检查通过后，不反复扩大测试范围。
