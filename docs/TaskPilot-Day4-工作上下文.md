## 2. 项目定位与总体计划

**TaskPilot：可评测的研发故障分析 Agent。**

用户提出故障分析任务，系统查询故障、统计类型、检索排障知识，生成带数字依据与来源引用的报告，保留 Trace，并由独立评测器判断任务是否完成。

典型任务：分析 payment-service 在固定 30 天内的故障，给出前三类问题和有依据的排查建议；证据不足时明确说明，不执行真实修复。

路线：Python、FastAPI、Pydantic、PostgreSQL、SQLAlchemy、Alembic，后续加入工具调用、LangGraph、pgvector、Streamlit、评测与 Docker Compose 部署。

原则：统计由代码完成；Agent 与评测分离；不开任意 SQL/Shell；区分事实、可能原因和待验证项；先单任务、低并发。

暂缓多 Agent、微调、长期记忆、MCP 服务端、生产修复、完整 Vue 前端和 Kubernetes。

原计划 D4 是“故障查询与统计，核对独立小样本”，D5 是“工具注册与参数 Schema”，D6 接模型工具调用，D7 整理 Trace。**D3 已提前完成底层查询统计，因此 D4 不重复实现 SQL，而是完成其面向应用的稳定契约与 HTTP 接入，保留 D5 的工具注册任务。**

## 4. Day 3 数据契约与验证结果

### 必须保留的数据语义

- 八字段：incident_id、is_synthetic、service、occurred_at、error_type、severity、message、resolution。
- 当前合成导入入口要求 `is_synthetic=true` 严格布尔值；拒绝未知字段。
- 必需文本去首尾空白后非空，service/error_type 大小写敏感；等级仅 P1/P2/P3。
- resolution 可缺失或 null，空白归一化为 null。
- 时间必须带偏移或 Z，统一 UTC，不猜测无时区时间。
- 查询范围 `[start_time,end_time)`，起点严格早于终点。
- 服务名去首尾空白后精确匹配。
- Top K 为正整数；数量降序、类别按 C 排序规则升序。
- 总数是全部匹配记录数，不能变成 Top K 数量之和；百分比分母同样为全部匹配记录数。
- 空结果总数 0、空分类列表。
- 当前明细无分页，面向小数据量；D4 不直接把无上限明细开放为通用 HTTP 接口。

## 6. 建议实施设计

### A. 最小接口契约

可采用 `GET /incidents/summary`，最终名称按仓库风格决定并记录。参数：

```text
service: 非空字符串，去首尾空白后精确匹配
start_time: 带时区日期时间
end_time: 带时区日期时间，晚于起点
top_k: 正整数，默认 3
```

默认沿用现有正整数语义；如新增上限，明确其用途、API 和底层的差异及测试，不静默改变契约。HTTP query 参数本身是字符串，应允许正常数字文本，拒绝 0、负数和非整数，不把 JSON 严格类型规则机械照搬。

响应至少包含：归一化服务、UTC 时间范围、top_k、全部匹配总数、分类数量与百分比、合成数据来源说明。字段名优先复用现有返回结构，经类型化响应明确约束，不直接暴露 ORM 或数据库异常。

空结果返回 200、总数 0、空列表，不作为 404。起止时间合法性和无时区拒绝规则不能丢失。

GET 查询中的 `+08:00` 必须正确 URL 编码。文档可用 `curl --get --data-urlencode`，避免裸 `+` 被解析为空格。

### B. 分层与资源生命周期

- 路由负责 HTTP 输入输出与状态映射；共享查询契约可供后续工具使用。
- 现有 repository 负责查询和统计，不复制 SQL 或重新用模型算数字。
- 只在确有重复规则需要时添加轻量 service，不为了分层创建无意义转发模块。
- 复用 Engine/Session 工厂；请求结束关闭会话，应用退出释放 Engine，不每请求重建连接池。
- Engine 创建不等于建立连接；基础启动和 `/health/live` 继续不要求数据库可达。
- 按实际生命周期与依赖注入设计，测试可替换数据库访问。
- 当前 SQLAlchemy 是同步调用，使用合适的同步路由/线程执行方式，避免在 async 路由直接阻塞事件循环。不为此全面切换异步驱动。
- 不在应用启动自动建表、迁移、导入数据。

### C. 错误语义

- 无效查询参数：统一明确的客户端错误，建议沿用 FastAPI 422；避免请求模型通过后又遗漏跨字段规则。
- 数据库连接等运行不可用：合理的 503 与通用说明；详细错误只按安全策略记录，不暴露密码、URL、SQL 或栈。
- 非预期编程错误不应全部吞掉并伪装成 503，也不能伪造空结果。
- 不新增开放配置转储或执行 SQL 的接口。
